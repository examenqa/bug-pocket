Implemented lifecycle behavior
Smoke and normal-startup profiles are deleted only after confirmed process closure. A directly spawned process must emit ChildProcess close. An exit event, success marker, successful kill request or fixed delay is insufficient.
For npm dev/start, the paused pre-import inspector identifies the actual Electron PID and executable. A Windows process-handle observer opens and holds that process handle before execution resumes. Cleanup requires matching WaitForExit proof and observer close, plus an independent npm-wrapper close. Missing, failed, late or mismatched ownership proof retains the profile.
A surviving npm/Vite launcher may be terminated during routine cleanup only after its owned Electron process closed normally with confirmed handle proof. The launcher must still close. Forced, abnormal or unknown Electron termination is a failure.
Teardown is bounded: defaults are 5 seconds for the graceful request/wait and 5 seconds for termination confirmation. Profiles are retained when process closure is uncertain. After closure, cleanup makes at most four attempts for known transient lock errors, with 100/200/300 ms waits and a fresh ownership check before each attempt.
The first failure is preserved. Termination, evidence, fixture-restoration and cleanup errors are appended as diagnostics. Late pipe/graceful-response errors also remain diagnostics. Startup CDP connection, commands and quit-response settlement are bounded. Existing smoke assertions and startup security, IPC, preload and HMR assertions are preserved.
The Windows handle observer reads control input through an explicit IO.StreamReader over OpenStandardInput, avoiding the blocking SyncTextReader ReadLineAsync path. The real observer and default Windows reparse-attribute subprocess are NOT RUN. Host tests use injected fixtures.
