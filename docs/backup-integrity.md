# Backup attachment integrity

Restore holds the existing exclusive operation barrier, extracts into staging, and
validates manifest paths, declared files, sizes and attachment metadata. It then
streams every declared attachment through SHA-256 and compares the digest to its
content_hash before closing live database handles or entering the file-swap phase.
SQLite integrity validation also completes before that phase.

Hashes generated by Bug Pocket use lowercase hex. Restore accepts uppercase or
lowercase hexadecimal hashes; digest comparison is case-insensitive. The existing
manifest rule still requires each filename to match its declared hash representation
and normalized extension. Filename/size checks alone do not establish integrity.

Any mismatch rejects the entire restore and removes staging. Existing live database,
sidecar and attachment files remain unchanged and the open database stays usable.
Missing manifest-declared payloads are rejected; attachments already recorded as
missing at export remain subject to the existing missing-attachment contract.
Legacy name-only archives retain their existing content verification as well.

This does not change backup scope: only local/active-workspace referenced attachments
are exported, pending captures are excluded, unrelated workspace blobs survive restore,
and post-commit failures retain the existing rollback behavior.
